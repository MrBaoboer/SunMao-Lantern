## 这是什么

一节能动手做的木工课，跑在网页里，面向**十岁往上的孩子和陪着他们的大人**。

它想解决「榫卯」这个词的老问题：课本上是一张剖面图，博物馆里是一件不许摸的展品，
两头都不告诉你**为什么木头能这样咬住木头**。这里的办法是让你自己做一遍 ——
十八步四幕，每一步都能亲手拖、亲手锯，每一道槽都是当场从毛坯上减出来的。

| 幕 | 步 | 在做什么 |
|---|---|---|
| **开场** | A1–A2 | 一盏灯，为一年收尾 —— 不用钉子，它凭什么立得住 |
| **认识榫卯** | B1–B3 | 凸的叫榫，凹的叫卯。直榫穿过去，夹榫落下来 |
| **做骨架** | C1–C8 | 开槽、切榫、凿透眼、铣柱窝、削细颈，十三根木条合龙 |
| **装点年味** | D1–D5 | 选花纹、装格心、糊纸贴花，最后拆开看一遍 |

<div align="center">
<img src="docs/img/unlit.png" width="860" alt="还没点灯的成品：四面万字纹格心糊着绵纸，四角立柱与出头的榫，一颗钉子也没有" />

十八步走完就是它。灯还没点，木作看得最清楚：四角出头的榫、四面镂空的棂条、糊在里面的绵纸。

做完之后还有四件事：**点灯**（按住引火，等它亮起来）、**猜灯谜**（答对一个，灯亮一分）、
**写心愿**（写在灯上，存成一张画）、**挂起来**（挂到你想挂的地方，最多六盏）。

## 自己做一遍

<div align="center">
<img src="docs/img/craft.png" width="420" alt="拖动凿子在顺枨顶面开出榫槽" />
<img src="docs/img/exploded.png" width="420" alt="三十六件构件的分层拆解" />
</div>

**加工是过程，不是一段动画。** 凿子压在哪条槽上，就只有那条槽在掉料；
拖一刀就少一层，手往回拖木头也不会长回去。刀够不着的地方文案会明说「另一头同样一锯」。

**拆开看，五层三十六件。** 底盘 5、上面的框 4、立柱 4、格心与纸 12、装饰与灯芯 11。
可以单看某一层，也可以拉着滑块把整盏灯慢慢摊开。

**不拦人。** 旁白没念完可以往前翻，任务没做完也可以往前翻。
需要动手的地方旁边一直留着「帮我加工」「帮我装上」—— 走同一段动画、同一组音效，跳过的只是手感。
连着三次装不上，吸附会自己放宽，帮助按钮自己递过来，不声张。

**跟不上的人也有路。** 旁白按 3.3–4 字／秒配速，讲道理的那几步再放慢一档，
生僻词带拼音（「榫卯，sǔn mǎo」）；灯谜答错不扣分、不重来，也不用红色。

## 怎么做的

无框架、无后端、无构建期资源：一个 [three.js](https://threejs.org) 依赖，一份 Vite 配置，产物是纯静态文件。

- **几何是算出来的。** 基本模数 a = 12 mm，以 a/12 = 1 mm 为最小刻度，每一个尺寸都过一道守卫 —— 不是整数毫米就当场抛错。十三件木构件由「毛坯盒减去若干带工序标签的切除盒」生成 —— 开槽、切榫、凿透眼、铣柱窝、开颈、刨装板槽……一共十三种工序标签，每一道都是一次精确的布尔减法。于是加工感不用画（CSG 标出哪些面是新切出来的，着色器据此提亮一档、压低粗糙度），穿模可以证伪（十七件两两求交，136 组配对重叠体积全为 0），面数也压得住（十七件包络合计 1152 个三角形）。
- **料是跟着刀走的。** 只掉刀压住的那条槽 —— 判定取的是既非进给轴、也非进刀轴的第三个轴，刃尖不落在这条槽的范围里就不动它。深度按刀数一层层推进，且只增不减；走过的区间只扩不缩。做法是把「刀在哪、走了多少」直接喂给 CSG，现算这一刀啃掉的那一块 —— 不是走完几刀之后把整道工序一次性开出来。工具是锯、凿、刨三样：柱窝和细颈是凿的活，装板槽是刨的活。
- **取景是算出来的。** 每一步只声明「必须完整看到多大一块」，相机自己算该退到多远：水平与垂直各算一次，取远的那个；界面占掉的画面也一并算进去 —— 旁白与坞的实际像素高由 `ResizeObserver` 量出来喂给三维。刀身同样算进去：凿自刃口向上还有 43 mm，而工件才 12 mm 见方。1440×900 与 390×844 走的是同一套反算。
- **音效是实时合成的。** 因为它必须可参数化 ——「两件一组时第二记高 2 个半音」「四根立柱到位音依次上行 +0/+2/+4/+6」，固定采样做不到。全部由 WebAudio 现场算：白噪声逐样本生成，木头是一组模态比 `[1, 2.76, 5.4, 8.9]` 的衰减振子。声音只有木头、纸、火三类物理来源，界面自己只留选中、完成、快门三记，其余三十来个「叮／唰／嗡」都被有意静音。
- **纹样是程序化的。** 两种纹样都由一组「二维线段 + 线宽」生成，再挤出成真实的镂空棂条：万字纹（默认）把卍字连续铺陈，四臂钩转落在单元角点上，相邻单元自然接续；麻叶纹是六边形棂格加每格六出放射。同一份线段数据同时供给灯上的棂条、地面的光斑、海报的脚线与选纹样的缩略图 —— 你选的纹样，四处永远是同一个。首图里地上那片光斑不是贴图，就是格心当聚光灯遮罩烘出来的。

`npm run verify` 会在 Node 端跑完 15 条几何断言；页面加载时也会跑一遍，右上角的「尺寸对照」可以随时调阅。

## 怎么操作

第一次进来会先讲一遍，右上角常留一个完整版。

| | |
|---|---|
| 两侧箭头 · `←` `→` · `空格` | 上一步、下一步 |
| 顶部小格 | 点一下跳到那一步 |
| 拖动 · 滚轮 | 转动、缩放。转到哪儿就停在哪儿，镜头不会自己跑回去 |
| `X` | 没有卷或坞挡着时，把灯笼拆开、调透明 |
| `Esc` | 收起菜单与大多数覆盖层；互动模块用左上角那枚返回 |

需要动手的步骤，底部中央会出现一个按钮；构件直接拖就行，每一次装配都只有一个合法方向 ——
呼吸的小箭头会指出来是哪个方向，推歪了会阻尼回弹并提示「沿着木条的方向推进去」。

界面默认浅色，右上角可以切到深色。夜里的场景（做完灯之后的那几步）本来就该是暗的，
界面会自动跟着变暗，但不动你存下的选择。

窄屏另有一套布局：两侧翻页挪到底部两角，屏幕两侧整片让给手指转动画面；工艺笔记改成顶部通栏、可折可滚。

## 跑起来

```bash
npm install
npm run dev
```

打开 <http://localhost:5173>。

```bash
npm run build     # 静态产物 → dist/
npm run verify    # 几何闭合验算（Node 端，无需浏览器）
npm run smoke     # 冒烟测试：真实浏览器走完十八步
npm run check     # 上面三样按顺序跑一遍
```

`npm run smoke` 与 `npm run shots` 需要一次性装好浏览器内核，之后不必再装：

```bash
npx playwright install chromium
```

冒烟测试用构建产物起一个静态服务，在 1440×900 与 390×844 两种画幅下各走完十八步；
桌面画幅还会把加工、装配、快速翻页、点灯、海报合成各跑一遍最短路径 ——
海报那条甚至会采样成图的中部算亮度标准差，防的是「合成成功但画面是空白」。
沿途盯着控制台报错、资源 404、未捕获异常、几何验算与刀刃朝向，任何一条都判失败。
加 `--shots` 会把每一步截图写到 `.shots/smoke/`：

```bash
npm run smoke -- --shots
```

本文档里的五张图也是从构建产物里拍的，模型或界面改动之后重出一遍即可，图与实现不会各说各话：

```bash
npm run shots
```

纯静态产物，任何静态托管都能放。当前 Demo 在 Vercel：`npm run build && npx vercel deploy --prod`。
`vite.config.js` 里 `base: './'`，产物用的是相对路径 —— 放在子路径下（如 GitHub Pages 的 `/repo/`）也不用改配置。

**环境**：Node 22.12+ 或 24+。Vite 8 自己还收 20.19+，但 Node 20 已于 2026 年 4 月停止维护 —— 这条下限是我们自己划的。
运行时只有一个依赖 [three.js](https://threejs.org)；
浏览器需要 WebGL 2（three 0.185 的渲染器只申请 `webgl2` 上下文，没有降级）与 ES2022（`build.target`）。
建议按 Chrome / Edge 111+、Safari 16.4+、Firefox 113+ 这条保守基线来 —— 它不是从构建配置反推出来的，
而是我们自己划的线；毛玻璃、`text-wrap: balance` 这类不支持时都原样降级，不影响使用。

## 项目结构

```
src/
  core/       模数体系、CSG 内核、构件参数、几何验算、全局状态
  render/     舞台与取景、材质、几何转换、格心纹样、装饰件、装配体、粒子特效
  interact/   单自由度约束装配、拖刀加工
  audio/      模态合成音效、旁白字幕、背景音乐
  ui/         界面层、图标、样式系统
  app/        分步引擎
  steps/      18 步主线内容
  modules/    四个互动模块、片尾与它们的旁白
  util/       补间与调度
  main.js     唯一的装配处：new 出每一层，塞进共享的 ctx，再把步骤表交给引擎
tools/
  verify-geometry.mjs   几何闭合验算（Node）
  smoke.mjs             冒烟测试（无头浏览器）
  shots.mjs             重出 README 的五张图
  make-script.mjs       旁白解说稿排版
```

构建产物 821 kB（gzip 225 kB），其中 three.js 单独一块 619 kB（gzip 155 kB），其余全部代码加起来 202 kB。
没有图片、字体或音频进产物，图标是内联的 data-URI SVG。

旁白与背景音乐留了挂载口，仓库里不含音频文件：旁白放 `public/audio/vo/{步骤号}.mp3`，
音乐放 `public/audio/bgm/{曲名}.mp3`，各自在同目录 `manifest.json` 里登记 `{ "ids": [...] }` 与 `{ "files": [...] }`。
没有音频时，字幕按语速模型独立走完同一套内容，一句不少。
全片旁白见 [旁白解说稿.md](旁白解说稿.md)，已分段断句、标好语速与停顿，可直接交给配音。
音效不在此列 —— 它们是实时合成的，没有文件。

## 隐私

写心愿模块不采集任何个人信息：没有输入框，愿望从现成的词里挑或拼，不要姓名手机号，不登录，不上传。
海报在设备本地用 Canvas 合成，编号是本机 `crypto` 生成的随机码，不含用户标识，也不可反查。
全站没有埋点、没有 Cookie、没有第三方脚本 —— 生产产物里不出现任何外部域名，
唯一的 `fetch` 是读自己 `public/` 下的那两份音频清单。
偏好（深色、声音、字幕）存在本机 `localStorage`；进度和写下的愿望也落在同一处，但下次打开一律不再读取，从头开始。
