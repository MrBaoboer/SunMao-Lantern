# 实现说明

几何、主线、刀具、取景、画面与音频为什么这么做。目标平台是桌面横屏优先，平板、手机竖屏与横屏各有一套布局；
浏览器基线见 [DEVELOPMENT.md](DEVELOPMENT.md#环境)。

## 1. 几何：算出来的，不是建出来的

| | |
|---|---|
| 模数体系 | `core/modulus.js`：全部尺寸为整数毫米（a = 12 mm，最小刻度 a/12 = 1 mm）。`a()` 带栅格断言，非模数尺寸当场抛错 |
| 节点参数 | `core/parts.js`：13 件木构件由「毛坯盒 − 若干带工序标签的切除盒」生成 |
| 布尔运算 | `core/boxcsg.js`：非均匀体素栅格 + 贪心面网格化。不做实时布尔，天然没有内部面 |
| 自检 | `core/verify.js`：17 条断言，页面加载即跑，控制台输出报告 |

由此顺带成立的几件事：

**加工感不用画。** CSG 给每个顶点标了 `aCut`（是否为加工新露出的面），木料着色器据此在同一个材质里同时表达主表面与切面，
切面比外表面浅一档。

**木纹长在木头上。** 年轮与顺纹在构件自己的坐标系里算（`vGrain = position`）。取世界坐标的话，料一被拖动、离位陈列或爆炸拆开，
纹理就在木头里流；转过来摆的料顺纹方向按世界轴取，会变成横纹。十三根各有各的花，靠 `seed`（搅动噪声取样点）与 `tone`（整体色差）。

**木纹要自己收敛。** 程序化花纹没有 mipmap：噪声的格子一旦细过一个像素，采到的就是随机相位，镜头一转整片木头就在沸腾；
三毫米宽的棂条压在灯笼纸上，读出来正是「纸在抖」。`fbmF()` 按屏幕空间足迹（`dFdx/dFdy`）逐层判断：这一层比一个像素粗就照常取样，
细过去就退回均值 0.5；年轮同理，掠射角上退成均值 0.42。退的是均值不是零，远处的木头只变平，不变色也不变暗。
MSAA 帮不上忙，它只管几何边缘，管不到三角形内部的着色频率。

**算得严丝合缝，画的时候让开一点。** 格心主体宽 8a 正好抵住两根立柱的内侧面，板厚 a/3 正好填满装板槽，几何上正确
（V-21 / V-22 钉着，[CLASH] 要求重叠体积为 0）。但两个面落在同一平面上，深度缓冲里就是同一个值，谁盖住谁由浮点末位决定，
镜头一动就翻，表现为格心四周与木条的接缝明暗闪烁。所以 `buildLatticeGeometry()` 画出来的那一片各边缩 `GAP = 0.3 mm`：
远大于深度分辨力（近裁面 2 mm 时，退到一千七之外也只有约 0.09 mm），又远小于一个像素。改的只是渲染网格，`core/parts.js` 那份验算实体不动。

**干涉检测与面数预算不用另写。** 实体单元可以直接展开成不重叠的盒体集合，「17 件构件两两是否穿模」就是一次集合运算：
136 组配对，重叠体积全部为 0。贪心面网格化之后面数也很低：一根开满槽的顺枨 86 tris，17 件包络体合计 1152 tris，上限 1400。

## 2. 两处节点的几何取舍

源码里标着 ★V-26 与 ★V-27 的两处，是把每个尺寸代入整数坐标之后按几何自洽性定下来的。

### V-26 · 中梁端部下半段去除

顺枨的开口槽只挖 z ∈ [2.5a, 3a]，槽底 z ∈ [2a, 2.5a] 是保留的余料。中梁端部下半段若也保留，两者在 y ∈ [3.5a, 4a] × z ∈ [2a, 2.5a] 正面干涉。
所以端部下半段横切去除（a/2 高 × a/2 长），露出的水平面（z = 2.5a，即双榫底面）落在顺枨槽底上，这个面才是承重肩。

### V-27 · 龙纹角花是带外挡边的方形盖板

柱头段高 2a（z 14a–16a），上枨框顶面在 z = 14a。用一个 a × a × a/2 的内腔套住柱头上部是锁不住的：角花底面在 z = 15.5a，
压舌够不到 z = 14a 的槽；内腔四壁又与柱头同域，柱头沿 +X 外拔时没有东西挡它。

所以角花是板：贴上枨框顶面（z ∈ [14a, 14a + a/3]），中开方孔套住柱头根部；压舌自板底面向下 a/6，落入横枨顶面压槽
（上枨框 `railB` 的 `PRESS_SLOT` 工序）；外缘出挑 a/6，正好横在柱头径向外拔的路径上。「结构副锁」靠这道外挡边成立。

## 3. 主线：十八步

| | |
|---|---|
| **开场** | A1 一盏灯为一年收尾 · A2 成品亮相与爆炸预览 |
| **认识榫卯** | B1 榫与卯（七千年、榫的三个部位、卯的三种规格）· B2 直榫 · B3 夹榫 |
| **做骨架** | C1 十三根木条 · C2 开槽与开叉 · C3 成「工」字 · C4 切榫头与凿透眼 · C5 底盘完成 · C6 上框（差别只有一处 + 装配）· C7 柱子开细颈 · C8 四柱合龙 |
| **装点年味** | D1 选纹样 · D2 装板 · D3 糊纸贴花上锁放灯芯 · D4 分层拆解 · D5 四个模块入口 |

主线看的是结构，不是视频：程序化几何最擅长表达的正是模数结构。观看型的段落不单独成步，
同一批料上的连续工序合成一步（开槽与开叉、切榫头与凿透眼、上框的加工与装配）。

旁白全片 1673 字，其中主线十八步 1450 字、念下来约七分钟，由 `npm run script` 从源码现算。

不能动的红线：C6 的对比动画（上框中部一刀不动）、D2 的三段式落堂装板、D3 首个角花的剖切演示、灯芯不提前点亮、
开场钩子与片尾闭环（两版都落在「新年快乐」）、语义色纪律。

## 4. 教学件与刀具：让动作和结果对得上

三个教学件（B1 榫与卯、B2 透榫、B3 夹榫）走真构件那条管线：`demoSolid()` 用毛坯减切除盒生成，内壁由 CSG 出面、照常受光，切面亮一档。
尺寸与真节点对齐：B3 的槽宽、榫舌、槽深直接取 `J2`，一根 12 见方的料正好三等分。

**凹进去的地方必须真的没有料。** 贴一块深色面片假装卯眼，眼睛读到的是一块凸起：它不透光、有自己的受光面。
这一步的全部意思恰恰是「凹进去的这一块叫卯」。

**刀具约定：刃口朝 −Z、柄在 +Z、刀身沿 +X。** 摆位直接搭一组正交基（`−Z → 攻角`，`+X → 走刀方向`，`Y = Z × X`），不用 `lookAt()`：
它转的是物体的 +Z，会把锯齿转到朝天；而加工镜头几乎都是朝下看，正好是它的退化情形，滚转角由内部容错分支随手定。
`npm run smoke` 每一步验「刃口与攻角的点积 ≥ 0.99」，基向量取反会立刻报 `dot=-1.000`。

**刀踩在料面上，不埋进料里。** 走刀线是刀走到底时刃尖所在的那条线，而它总比口子长（C4 的透眼 4 mm 宽，刀要走 15.6 mm，手上才有一段够拖的行程）。
把刀直接摆在这条线上，第一刀还没去料它就已经插在实料里。所以刀的高度是每帧探出来的：沿刀身工作端取五处（跨度见 `buildTool` 的 `reach`），
各从刀上方沿进刀方向打一条射线，取最高的那个面，把刃尖放上去，夹在走刀线与开工时的外表面之间。料啃掉多少，面就低多少，刀跟着沉；
走到还没开口的那一段，刀自己抬起来。取最高而不是只探刃尖底下那一处，因为刀是刚体：架在最高处，底下有坑就悬着。
代价是容不下刀的口子（透眼 4 mm，与凿身同宽）刀就停在面上，这是对的，料照旧一层层地少。

### 料要跟着刀走

「工序」是布尔开关，走刀是连续运动。`buildPart(id, ops, carve)` 把两者接上：`carve` 带着刃尖位置、进给轴、进刀轴与进度 `t`，据此现算这一刀啃掉的那一块。

- **这一刀压在哪个盒上。** 判据是既非进给轴、也非进刀轴的第三个轴：刃尖必须落在切除盒的范围内。进给轴由 `to − from` 定，进刀轴由 `faceNormal` 定，
  两者指同一个轴时判据失效。顺枨顶面两条槽因此要走两趟。
- **啃到多深。** 自入刀面向里推进 `t = (已完成刀数 + 本刀比例) / 总刀数`。只增不减，手往回拖木头不会长回去。
- **扫到哪儿。** 进给轴上按刃尖真正走过的区间裁一刀。连续的长槽一点点变长再变深，两个分开的孔则是刀经过谁、谁才掉料。
  走刀线要完整跨过它要开的那几处，起点落在孔里的话孔的外半边永远扫不到。
- **走完的那几趟连区间一起记。** 第一条判据刻意不看进给轴，横截位置相同、只沿走刀方向分开的两处料（横枨的两个透眼、两个柱窝）
  会被前一趟的记录一并认领，第二个孔在刀落下之前就通了。所以 `carveFinish()` 同时记下那一趟刃尖扫过的区间，`laneCovers()` 用它做交集判断。
  `verify.js` 的 `[CARVE]` 钉住：第一趟走完，另一处必须还是实心；第二趟刚下刀，第一处不许长回去、第二处不许提前成形。
- **一处一趟刀，一道工序一条走刀线。** 透眼与柱窝各两个，一个孔一趟；通长的装板槽一刨到底。中梁三道各给各的走刀线与机位：
  截短自顶面横跨料宽，开叉口自端面顺着槽往里剔，切承重面自端面横着推。

几何按 1/32 量化重建。这些构件贪心网格化之后只有几十到一百多个三角形，重建一次比画一帧还便宜。

**工具只有锯、凿、刨三样。** 凿是单面斜磨的剖面挤出，刃宽 4 mm，与它要凿的槽同宽；柄八棱，带挡铁与铁箍。锯齿距 1.5 mm。
柱窝与细颈是凿的活，装板槽是刨的活。不用电动铣刀：那么大一个机身杵在 12 mm 见方的料旁边，读出来是台角磨，而这一课讲的是不用钉子的手作木工。

## 5. 交互：单自由度约束

所有拖拽一律是 1 自由度约束，`interact/assembly.js` 实现：

- 每件构件只有一个合法运动方向（`ASSEMBLY` 表）；错误方向阻尼回弹，配该步专属的引导文案。
- 主线吸附阈值 5–6 mm；教学件走轻量的 `simpleDrag`，不设毫米阈值，推过全程 88% 即坐实。
- 连续 3 次未成功，阈值悄悄放宽到 12 mm，并主动提供帮助。有楔紧段的那一步不放宽，否则末段回弹又变回不可达。
- C8 立柱末段 2 mm 楔紧（`J3.WEDGE_LEN`）：速度曲线压至 40%，未推到底则回弹。这一档必须排在吸附判定之前，两条门槛互相包含，写在后面就是死代码。

每一处动手的地方都并排放着一个不动手的出口：装配是 `drag.autoSeatAll()`（「帮我装上」），加工是 `mach.autoRun()`（「帮我加工」）。
两条路走同一段动画与同一组音效，按「下一步」时引擎走的也是它们（[UI.md](UI.md#五条规矩)）。

剖切与拆解是常驻能力，不是一次性演示：任意时刻按 `X`，对当前模型做爆炸与半透，两根滑杆连续控制。

## 6. 取景：算出来的，不是摆出来的

按笔记本画幅试出来的机位换个画幅就不成立。竖屏手机 390×844 的水平视场只有约 18°（垂直 38°）：同一个 120 mm 宽的灯笼在笔记本上绰绰有余，
在手机上直接裁掉两边。所以每一步只声明「必须完整看到多大一块」，距离由代码算：

```js
cam: { az: 62, el: 12, dist: 470, target: AIM_LANTERN, fit: FIT_LANTERN }   // fit = { r: 98, h: 110 }
```

`stage.setRecommended()` 拿到 `fit` 后，水平与垂直各算一次装得下所需的距离，取远的那个，再与 `dist` 取最大值：只往后退，不往前凑，宽屏上的取景意图原样保留。

**界面占掉的画面也算进去。** `hud` 实时量出常驻界面与坞的上下边界（`getClientRects`，fixed 元素的 `offsetParent` 恒为 null），交给 `stage.setSafeArea()`：
可用画幅按 `(高 − 上 − 下) / 高` 折算，下限 0.62；撑到下限时上下等量撑开，占比与中心同出一带，多出来的那一截不会全溢向下方压在旁白上；
主体按这一带整体上抬。画幅或界面高度一变，`resize` 用同一份声明重算。

**缩放上限让给取景。** 轨道控制在 `update()` 里把相机距离夹进 `[minDistance, maxDistance]`，推荐机位也不例外。
D4 分层拆解在手机竖屏上要退到一千七百毫米，被 1400 夹住就等于声明作废。`setRecommended()` 会把上限抬到至少容得下这一步。

**把刀也算进去。** 工件是 12 mm 见方的一根料，凿自刃口向上还有 43 mm 刀身。`AIM_BENCH` 把目标点抬起 16 mm、`FIT_BENCH` 按「刀 + 工件」给高度，每一趟走刀都有自己的机位。

**翻页是转场，不是跳切。** 十八步都只是下达一个机位，相机自己走过去；`snapToRecommended()` 只留给真正另起一个场的三处（封面、互动模块、拍图脚本）。
走球坐标：方位角、仰角、距离各自插值，方位角走最短弧。按位置直插会走成一条弦，方位角差得多的两步相机会从主体中间穿过去。

转场是一段定长的弧：速度从零起、中段最高、再落回零（首尾一二阶导都为零的缓动），到点精确坐在机位上。
指数追赶两头都不对，前半程一口气走掉大半（读作「甩」），后半程永远差一点（读作「飘着不落地」）。
时长按这次要跨的弧长给（0.9–2.2 秒，推轨与目标平移换算成等效度数取最大）。封面自转这类逐帧的小挪动走临界阻尼的微跟随，不算转场。

**光跟着镜头走。** `setMood()` 默认在 0.7 秒里渐变：相机在转、光却一格跳变，两件事就对不上（A2 对 A1 的背景差四十多级，跳变读作「忽然变白」）。
渐变的两端做快照、按显式的 t 插值，走完把目标逐项原样写死，收地面这类副作用只挂在真正到位上。互动模块传 `{ snap: true }`，那里是硬切进另一个场。

**用户转过的画面不许被界面推走。** `setRecommended()` 会清掉「用户接管过」这个标记，而底部提示一换字数，`ResizeObserver` 就会经 `setSafeArea()` 绕到它，
所以内部重算要传 `{ keepUser: true }`。动手的步骤里 `stage.hold(true)` 连这次重算一起冻住。

**小变化不重新取景**（`REFRAME_MIN = 48 px`，与上一次真正据以取景的那一组比）。字幕一句一行、两行来回换，每变一次就重算机位的话，
相机在飘，主光目标点跟着飘，阴影贴图整体位移，纸面上棂条的影子持续爬动，看上去是「东西停着却在颤动」。坞这一级的变化（上百像素）照样重新取景。

**能不动就不动。** 相邻两步的方位角尽量落在同一个家族里。真要绕的只有两类：主体换了朝向（B1/B2 要看进卯眼，只能站到 −X 那一侧），
以及一步之内交代完了、该换个角度看结果（B2 咬合后绕到出头那一侧，否则「看，穿出来了」说完画面上什么也没发生）。

界面自己怎么给三维让位，见 [UI.md](UI.md#底部)。

## 7. 画面：曝光与背景

浅色主题四路光的总辐照（`MOODS.light.*`）只留了约三成余量：再上调就越过 ACES 的膝点，年轮与顺纹被推平，木头变成奶白色，切面提亮那一档也不可读。
想让画面更亮，调背景与 bloom。

背景不是平色：`makeBackdrop()` 在远平面画一块屏幕空间渐变，主体背后一圈暖光晕，四周压暗。四种基调、两套主题共用一套实现，每种基调只给一对颜色；
夜色不跟主题走，灯笼只有在暗处才亮得起来。

**改背景色等于同时在改 bloom 阈值。** `setMood()` 把阈值取成 0.86 与「本档背景最亮处 + 0.02」的高者：把背景压暗，阈值跟着掉，参与高光溢出的东西反而变多。

**浅色三档不开高光溢出（`bloom: 0`）。** 键光下的绵纸是全场最亮的面，亮度贴着阈值往上冒：走 composer 的档位上纸面自己越线起辉，辉光糊回棂条与窗花，
读出来是「舞台中央蒙了一层白」。真 GPU 实测 A2 约 1.8% 的像素被加亮最多约百级，全在纸面上；直出路径（低配档）没有这层白。
深色与夜色照旧留着溢出：那里的纸只有约三成亮度，越线的只有灯焰。

**绵纸按真实读数给不透明度。** 反射光下基本不透（0.86），点亮后再实一点（0.96），透光交给 `emissiveIntensity`。
压到 0.55 的话，不点灯时就能一眼看穿到对面那片格心，两层万字纹叠在一起，整盏灯读出来是个玻璃罩子。

## 8. 音频

### 为什么音效是合成的

同一记咬合音要能升高两个半音，十三次落料要能随机浮动，四根立柱到位要依次上行，走刀音要随刀数升高。现成采样做不到。

`audio/sfx.js` 用四类物理导向的基元合成：**击励共振**（一记宽带冲击打进一组高 Q 带通滤波器，滤波器自己振铃衰减；
模态比取木条自由-自由弯曲的近似值 1 : 2.76 : 5.4 : 8.93，木料阻尼大、余韵短）；**拨弦**（Karplus-Strong 弦模型，「做完一件事」是一记五度的拨弦余韵）；
**颗粒**（几十毫秒里的一撮微小冲击：木纤维断裂、纸的窸窣、火星）；**气流**（带通噪声扫频加包络，锯与刨再叠一层低频调制当齿感与卷屑感）。
每记有 ±1.2% 音高与 ±18% 幅度的随机活口。全部事件过同一间生成的小混响（0.35 s，湿量极低）落进限幅总线，声音才「落在桌上」。

### 只留有物理来由的声音

音效表 20 记（18 记单发加 2 记循环）：

| | |
|---|---|
| 木作 | 咬合、楔紧、轻敲、落料、坐实、滑动、装板 |
| 刀具 | 锯、凿、刨、木屑 |
| 纸与装饰 | 纸、笔触、结与流苏 |
| 火 | 点亮、引火、燃烧（后两记是循环音） |
| 界面 | 选中、做完一件事、快门 |

各种「叮」「唰」「嗡」（UI 提示音、光效音、剖切音、时间轴音）不在其列：没有物理来由，也不构成信息，界面上已经能看见的事不需要再响一声。
这些编号收在 `MUTED` 里，调了不响；有物理来由的由 `ALIASES` 折到这 20 记上。名字一律留着，好让人看出它是有意去掉的。

## 9. 不做的与替代做法

| 项 | 本版 | 原因 |
|---|---|---|
| 触觉反馈 | 视觉微反馈 + 音频代偿，时序不变 | 桌面浏览器无振动 API |
| M4 真 AR | 程序化全景背景，可挂多盏并拍照 | 未接入 WebXR。全景在桌面与手机上表现一致，也不需要相机权限 |
| M3 笔顺动画 | 逐字分段揭示 + 每段笔触声 | 真实笔顺需 60–80 字的 SVG path 序列，属内容交付物；代码已留接入点 |
| M3 二维码 | 海报上以文字呈现编号 | 不做假二维码。接真 QR 需引入唯一的外部依赖，留待产品定稿 URL 后加 |
| 龙纹 / 祥云纹样 | 程序化意象化处理（回旋脊线、云头曲线） | 无外部模型资产。结构职能与槽位对位不变 |
| 格心纹样 | 麻叶 / 万字 两选一 | 冰裂纹的递归剖分在小尺寸格心上读不出「线不相交」，像随机网格 |
| 烟花模块 | 不做，四扇门只有 M1–M4 | 它与这盏灯没有结构或知识关系，只是一段粒子表演；片尾接在「四件事都做完」之后，落点更实 |
